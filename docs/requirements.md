## 0. 技术选型（建议，可调整）

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 主语言 | Python 3.12（conda 环境） | 文档允许 C/Python；客户端播放、ABR、强化学习、数据分析都在 Python 生态内最省事。若想拿"C 兼容"印象分，可后期用 C 重写服务端传输核心 |
| 并发模型 | 服务端 `asyncio`（或 `threading`，每连接一线程） | 满足"并发处理多个客户端" |
| 分片 | FFmpeg：多码率转码 + `-f segment`/`-f hls` 切 5 s TS | 文档指定 |
| 播放器 | `ffplay` / `mpv` 从 stdin 读取 TS 流（TS 天然可拼接） | WSLg 已可显示 GUI |
| 日志 | SQLite（`sqlite3` 标准库） | 文档指定 |
| 网络模拟 | ① 应用层令牌桶限速 + trace 回放（主，可复现）；② Linux `tc tbf/netem`（辅，演示用） | WSL2 内核已编译 tbf/netem 模块 |
| ML | NumPy（Q-Learning 表格法）；可选 PyTorch（DQN） | 文档推荐 Q-Learning |
| 抓包 | Wireshark / tshark，可选写一个 Lua dissector 解析自定义协议 | 文档指定工具 |

## 1. 视频素材与分片（服务端离线部分）

- [ ] **V-01** 准备 1 段源视频（≥ 2 分钟，1080p，画面变化丰富便于体现码率差异），命名如 `ocean`
- [ ] **V-02** 定义码率阶梯（bitrate ladder），例如：

  | 档位 | 分辨率 | 码率 |
  | --- | --- | --- |
  | 0 | 360p | 800k |
  | 1 | 480p | 1200k |
  | 2 | 720p | 2500k |
  | 3 | 1080p | 5000k |
  | 4 | 1080p | 8000k |

- [ ] **V-03** 用 FFmpeg 转码各档位，并按**固定 5 s** 切成 TS 分片（固定 GOP/关键帧间隔 = 5 s 的整数分之一，保证各档位分片边界对齐，切码率时无缝）
- [ ] **V-04** 分片命名：`{name}-{res}-{bitrate}-{seq}.ts`，例如 `ocean-1080p-8000k-0.ts`
- [ ] **V-05** 生成清单文件（manifest，JSON）：视频名、分片时长、分片总数、码率阶梯、每个分片大小；客户端启动时先拉取
- [ ] **V-06** 分片脚本可一键运行：`scripts/segment.sh <input> <name>`

## 2. 服务端（必做）

- [ ] **S-01** 基于 TCP 监听端口，接受客户端连接
- [ ] **S-02** 并发处理多个客户端（至少 3 个同时请求、互不阻塞）
- [ ] **S-03** 实现自定义应用层协议（见 §4），支持：获取 manifest、按文件名请求分片、错误响应（不存在 / 非法请求）
- [ ] **S-04** 记录每个分片的发送日志到 SQLite：客户端 ID、分片名、序号、码率、字节数、开始/结束发送时间、吞吐量
- [ ] **S-05** 提供日志导出（CSV）或查询脚本，供测试报告使用
- [ ] **S-06** 可配置的应用层限速（令牌桶），支持按 trace 文件动态改变带宽 —— 用于"带宽骤降"演示和可复现实验
- [ ] **S-07** 优雅退出、异常连接处理（客户端中途断开不影响其他客户端）

## 3. 客户端（必做）

- [ ] **C-01** 连接服务端，拉取 manifest
- [ ] **C-02** 循环按序号请求分片，文件名由 `名称-分辨率-码率-序号` 拼接
- [ ] **C-03** 分片保存至 `download/` 目录
- [ ] **C-04** 接收后实时送入播放器播放（下载线程与播放线程分离，中间是缓冲区）
- [ ] **C-05** 维护播放缓冲区模型：缓冲时长、卡顿（rebuffer）检测与计时、启动时延
- [ ] **C-06** **基于规则的 ABR**，至少实现一种，建议两种用于对比：
  - 吞吐量法（最近 N 个分片下载速率的调和平均 × 安全系数）
  - 缓冲区法（BBA：缓冲区 < reservoir 选最低档，> cushion 选最高档，中间线性映射）
- [ ] **C-07** ABR 模块抽象成统一接口 `choose(state) -> level`，便于替换为 RL 算法
- [ ] **C-08** 本地缓存管理：分片播放完成后自动删除；程序退出时清空 `download/`
- [ ] **C-09** 客户端侧日志（每个分片：选择码率、下载耗时、测得吞吐、缓冲区大小、卡顿时长），用于 QoE 计算
- [ ] **C-10** 支持无界面（headless）模式：不开播放器、只模拟播放时钟，用于批量实验和 RL 训练

## 4. 分片协议（设计文档需要）

- [ ] **P-01** 定义报文格式，示例（大端序）：

  ```
  +--------+---------+--------+--------+-------------+----------------+
  | magic  | version | type   | flags  | request_id  | payload_len    |
  | 2 B    | 1 B     | 1 B    | 1 B    | 4 B         | 4 B            |
  +--------+---------+--------+--------+-------------+----------------+
  | payload (payload_len bytes)                                       |
  +-------------------------------------------------------------------+
  ```

  type：`GET_MANIFEST` / `MANIFEST` / `GET_SEGMENT` / `SEGMENT` / `ERROR` / `BYE`
- [ ] **P-02** 分片数据可带校验（CRC32 / SHA-256）以验证完整性
- [ ] **P-03** 在协议文档中画出报文格式图、交互时序图

## 5. 测试与评估（必做）

- [ ] **T-01** 网络环境模拟：固定带宽（如 1 / 2 / 4 / 8 Mbps）、带宽骤降（8 → 1 Mbps）、波动 trace（可用公开的 FCC / 3G / Norway HSDPA trace）
- [ ] **T-02** 指标计算：
  - 卡顿率（rebuffer 时间 / 总播放时间）、卡顿次数、启动时延
  - 平均码率、码率切换次数/幅度
  - **PSNR**：用 `ffmpeg -lavfi psnr` 计算各档位相对源视频的 PSNR，按实际播放的档位序列加权得到会话 PSNR
  - QoE（线性模型）：`QoE = Σ q(R_k) − μ·Σ rebuffer_k − Σ |q(R_{k+1}) − q(R_k)|`
- [ ] **T-03** 在不同带宽下对比各 ABR 算法，输出图表
- [ ] **T-04** Wireshark 抓包，截图展示自定义协议交互、TCP 窗口/吞吐变化

## 6. 扩展功能（附加分，上限 25）

| 编号 | 扩展项 | 分值 | 建议 |
| --- | --- | --- | --- |
| **E-01** | 智能码率自适应（Q-Learning / DQN） | 25 | **主攻**，单项即可拿满附加分 |
| E-02 | 端到端 AES 加密 | 10 | 成本低（AES-GCM，几十行），建议做作为保底 |
| E-03 | 滑动窗口流式处理 | 15 | 可选：分片拆成定长块并行/乱序到达，接收端滑动窗口重组 |
| E-04 | 动态路径优化 | 25 | 工作量大（需多中继节点 overlay + Dijkstra/测量），暂不建议 |
| E-05 | 自定义开放问题 | 10–25 | 需期中提交 Proposal，暂不考虑 |

**E-01 细化：**

- [ ] **E-01a** 搭建离线仿真环境（基于吞吐 trace + 分片大小表 + 缓冲区模型），与真实客户端共用 ABR 接口
- [ ] **E-01b** 状态离散化：上次码率档位、缓冲区区间、吞吐预测区间；动作 = 码率档位；奖励 = 单步 QoE
- [ ] **E-01c** Q-Learning 表格法训练、保存 Q 表；（可选）DQN 版本
- [ ] **E-01d** 将训练好的策略接入真实客户端在线运行
- [ ] **E-01e** 与规则 ABR 的 QoE 对比实验与图表（训练 trace / 测试 trace 分开）

**E-02 细化：**

- [ ] **E-02a** 握手阶段协商会话密钥（预共享密钥或 ECDH）
- [ ] **E-02b** 分片 payload 用 AES-GCM 加密，客户端解密后写入 `download/`
- [ ] **E-02c** Wireshark 截图对比加密前后

## 建议目录结构

```
StreamWise/
├── server/            # TCP 服务端、限速器、SQLite 日志
├── client/            # 下载器、缓冲区、播放器集成、缓存管理
├── abr/               # 规则 ABR + RL ABR（统一接口）
├── common/            # 协议编解码、配置
├── sim/               # 离线仿真环境、RL 训练脚本
├── scripts/           # FFmpeg 分片、tc 限速、批量实验
├── traces/            # 带宽 trace
├── media/             # 源视频与分片（git 忽略）
├── analysis/          # 指标计算与画图
├── tests/
└── docs/              # 设计文档、测试报告、用户手册、poster
```

## 建议里程碑

1. **M1 环境 + 分片**：conda 环境、FFmpeg 多码率切片、manifest（V-*）
2. **M2 端到端跑通**：协议 + 服务端 + 客户端 + 播放 + 缓存清理（S-01~03, C-01~04, C-08）
3. **M3 规则 ABR + 日志 + 限速**（S-04~06, C-05~07, C-09）
4. **M4 仿真与 RL**（C-10, E-01）
5. **M5 实验与评估**（T-*），**AES**（E-02）
6. **M6 文档、Poster、演示排练**（D-*, R-*）
