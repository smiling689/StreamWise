## 范围

必做部分加三个扩展项，共 50 分（E-01、E-02、E-03，见 §8）。附加分上限 25 分，多做的扩展用于防止部分扣分。

## 0. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.12 | 作业允许；播放器集成、ABR、数据分析最省事 |
| 环境 | Conda（`environment.yml`） | 可复现；无需 root 即可获得 FFmpeg |
| 并发模型 | `asyncio` 服务端（每连接一个 task） | 支持并发客户端 |
| 分片 | FFmpeg 多码率转码 + 5 s TS 分片 | 作业指定 |
| 播放器 | `ffplay`（或 `mpv`）从 stdin 读取 TS 流 | TS 可直接拼接；WSLg 可显示画面 |
| 日志 | SQLite（标准库 `sqlite3`） | 作业指定 |
| 网络模拟 | 应用层令牌桶限速 + trace 回放（主，可复现）；Linux `tc tbf/netem`（辅，演示用） | |
| 抓包 | Wireshark / tshark | 作业指定 |

## 1. 视频素材与分片（服务端离线部分）

- [x] **V-01** 准备源视频（≥ 2 分钟，1080p，画面变化丰富以体现码率差异），如 `ocean`
- [x] **V-02** 定义码率阶梯，例如：

  | 档位 | 分辨率 | 码率 |
  | --- | --- | --- |
  | 0 | 240p | 400k |
  | 1 | 360p | 800k |
  | 2 | 480p | 1200k |
  | 3 | 720p | 2500k |
  | 4 | 1080p | 5000k |
  | 5 | 1080p | 8000k |

- [x] **V-03** 用 FFmpeg 转码各档位，切成**固定 5 s** 的 TS 分片；固定 GOP 使各档位分片边界对齐，切换码率时无缝
- [x] **V-04** 分片命名：`{name}-{resolution}-{bitrate}-{seq}.ts`，例如 `ocean-1080p-8000k-0.ts`
- [x] **V-05** 生成 JSON 清单（manifest）：视频名、分片时长、分片数、码率阶梯、各分片大小；客户端启动时先拉取
- [x] **V-06** 一键分片：`streamwise-media segment <input> --name <name>`

## 2. 服务端（必做）

- [x] **S-01** 监听 TCP 端口，接受客户端连接
- [x] **S-02** 并发服务多个客户端（≥ 3 个同时请求，互不阻塞）
- [x] **S-03** 实现应用层协议（§4）：获取 manifest、按文件名请求分片、错误响应（不存在 / 非法请求）
- [x] **S-04** 每个分片的发送记录写入 SQLite：客户端 ID、分片名、序号、码率、字节数、开始/结束发送时间、吞吐量
- [x] **S-05** 日志导出（CSV）或查询脚本，供测试报告使用
- [x] **S-06** 可配置的应用层限速（令牌桶），支持回放带宽 trace —— 用于带宽骤降演示和可复现实验
- [x] **S-07** 优雅退出；客户端中途断开不影响其他客户端

## 3. 客户端（必做）

- [x] **C-01** 连接服务端并拉取 manifest
- [x] **C-02** 循环按序号请求分片，文件名由 `名称-分辨率-码率-序号` 拼接
- [x] **C-03** 分片保存至 `download/` 目录
- [x] **C-04** 接收后实时送入播放器播放（下载与播放通过缓冲区解耦）
- [x] **C-05** 播放缓冲区模型：缓冲时长、卡顿检测与计时、启动时延
- [x] **C-06** **基于规则的 ABR**，实现两种用于对比：
  - 吞吐量法：最近 N 个分片吞吐的调和平均 × 安全系数
  - 缓冲区法（BBA）：低于 reservoir 选最低档，高于 cushion 选最高档，中间线性映射
- [x] **C-07** 统一 ABR 接口 `choose(state) -> level`，算法可互换
- [x] **C-08** 缓存管理：分片播放完后删除；程序退出时清空 `download/`
- [x] **C-09** 客户端逐分片日志：所选档位、下载耗时、测得吞吐、缓冲区大小、卡顿时长（用于计算 QoE）
- [x] **C-10** 无界面模式：不开播放器、模拟播放时钟，用于批量实验

## 4. 分片协议（设计文档需要）

- [x] **P-01** 定义报文格式，示例（大端序）：

  ```
  +--------+---------+--------+--------+-------------+----------------+
  | magic  | version | type   | flags  | request_id  | payload_len    |
  | 2 B    | 1 B     | 1 B    | 1 B    | 4 B         | 4 B            |
  +--------+---------+--------+--------+-------------+----------------+
  | payload (payload_len bytes)                                       |
  +-------------------------------------------------------------------+
  ```

  类型：`GET_MANIFEST` / `MANIFEST` / `GET_SEGMENT` / `SEGMENT` / `ERROR` / `BYE`
- [x] **P-02** 可选的分片完整性校验（CRC32 / SHA-256）
- [x] **P-03** 设计文档中给出报文格式图与交互时序图

## 5. 测试与评估（必做）

- [x] **T-01** 网络场景：固定带宽（如 1 / 2 / 4 / 8 Mbps）、带宽骤降（8 → 1 Mbps）、波动 trace
- [x] **T-02** 指标：
  - 卡顿率（卡顿时间 / 总播放时间）、卡顿次数、启动时延
  - 平均码率、切换次数与幅度
  - **PSNR**：用 `ffmpeg -lavfi psnr` 计算各档位相对源视频的 PSNR，按实际播放档位加权得到会话 PSNR
  - QoE（线性模型）：`QoE = Σ q(R_k) − μ·Σ rebuffer_k − Σ |q(R_{k+1}) − q(R_k)|`
- [x] **T-03** 在不同带宽下对比各 ABR 算法并出图
- [~] **T-04** Wireshark 抓包，展示协议交互与 TCP 吞吐变化

**E-01 智能码率自适应**

- [x] **E-01a** 基于带宽曲线的离线仿真器，规则与真实客户端/服务端一致，并用真实会话验证
- [x] **E-01b** 表格型 Q-Learning 智能体，复用统一 ABR 接口（状态：上一档位、缓冲区、吞吐估计、吞吐趋势；奖励：单分片 QoE）
- [x] **E-01c** 在合成曲线和真实 3G 曲线上训练，模型选择只使用验证集
- [x] **E-01d** 训练好的模型直接在真实客户端运行（`--abr qlearning`）
- [x] **E-01e** 在留出测试曲线（仿真）和真实系统中与规则算法对比 QoE

**E-02 端到端 AES 加密**

- [x] **E-02a** 在握手中完成密钥交换（X25519 + HKDF-SHA256），每个连接使用新密钥，可选预共享密钥用于身份认证
- [x] **E-02b** 握手之后的所有消息使用 AES-256-GCM 加密；消息头受认证保护；可检测重放和乱序
- [x] **E-02c** 服务端支持 off / optional / required 三种模式；缺少加密或密钥错误时给出明确错误
- [x] **E-02d** 测试篡改、重放、密钥错误和明文泄露；Wireshark 中可见加密消息
- [x] **E-02e** 测量开销（CPU、字节数、无限速吞吐量），并与明文传输对比 QoE
